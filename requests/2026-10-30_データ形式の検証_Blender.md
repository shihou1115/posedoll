# 改良要望：シーン JSON のデータ形式を Blender で検証する（2026-10-30）

## 目的
シーン JSON（v2）が、他のツールでも同じポーズを再現できる「受け渡し用の形式」になっているかを確かめる。
Blender での再現を検証に使う（Blender との本格的な連携方針は保留中。今回は形式の確認だけ）。

## 現状で予想される不足（検証で確かめる）
1. **骨格の基準形がファイルに入っていない**：JSON にあるのは関節の回転・腰の位置・体型の倍率だけ。
   関節の親子関係と基準の長さ（例：肩→ひじ 0.28m）は app.js の中にしかなく、ファイル単体では再現できない。
2. **約束事が書かれていない**：単位（m）、座標系（Y が上・人形は +Z 向き・本人の左が +X）、
   回転順（XZY）、角度の単位（度）、左右反転の規則がファイルにも文書にもまとまっていない。
3. **カメラが入っていない**：書き出し枠の視点・画角・出力サイズがないため、同じ OpenPose / 深度画像を作り直せない。
4. **小道具は種類名だけ**：形状の寸法はコード内にある。
5. **手指の親指の付け根**：固定の向き（thumbBase）がコード内にだけある。

## 検証の手順
1. デッサン人形ポーザーで検証用シーンを数種類作る（各プリセット、手の形、体型を変えたもの、2人、小道具あり）。
   各シーンについて、JSON と一緒に「全関節と OpenPose 点のワールド座標」「書き出し画像（OpenPose・深度）」を保存する
   （smoke_test.js と同じ方法で自動化できる）。
2. Blender 側で JSON を読み込むスクリプトを作り、アーマチュア（または空オブジェクトの階層）で同じポーズを組む。
   - 座標変換：three.js（Y 上）→ Blender（Z 上）は (x, y, z) → (x, -z, y)。回転はクォータニオン経由で変換する。
   - 回転順 XZY（three.js の Euler 'XZY'）を正しく解釈できているか確認する。
3. Blender 側の関節のワールド座標を書き出し、デッサン人形ポーザー側の値と比べる（誤差 1mm 以内を合格の目安）。
4. カメラ情報を加えた場合は、Blender でレンダリングした OpenPose 点の画面位置も比べる。

## 期待する成果物
- `docs/scene-format.md`：シーン JSON の仕様書（上の「約束事」を明文化、版の管理方法も）。
- JSON への追加項目（後方互換を保つ）：
  - `skeleton`（関節の親子関係・基準の位置・回転順・単位・座標系）を任意で書き出せるようにする
  - `camera`（位置・注視点・画角・出力サイズ）
- `tools/blender_import.py`：Blender で JSON を読み込んでポーズを組むスクリプト（Blender 内で実行する前提。ネット不要）。
- 検証結果のメモ（どのシーンで何 mm の誤差だったか）。

## 補足
- Blender は Claude から操作できる（Blender MCP 接続済み。Blender を起動しておく必要あり）。
- 検証で見つかった形式の問題は、このファイル末尾に追記してから直すこと。

## 検証で見つかった形式の問題（2026-10-30 追記）
- 予想 1〜5 はすべてそのとおりだった（骨格・約束事・カメラ・小道具の寸法・親指の付け根がファイルに無い）。
- **予想外の問題**：`cam`（v1.2 から保存）があっても、書き出し画像の構図は保存した値だけでは決まらなかった。
  `cam.fov` が画面のカメラの画角で、書き出し枠はその一部なので、**ブラウザの窓の大きさによって書き出しの構図が変わっていた**
  （同じ JSON を窓 3 種類で開くと、首の点の縦位置が 114.8 / 178.5 / −19.5px）。アプリの中だけで使っていても起きる問題。

## 対応（v1.7、2026-10-30）
- **形式 2.1**（`formatVersion: "2.1"`。`v: 2` のまま、2.0 のファイルも読める）。ファイル保存時だけ次を付ける（アプリは読み込みに使わない）:
  - `figures[i].skeleton`：ノードの親子・`offset`（体型反映済み）・固定ノードの `rest`/`scale`（headGroup・親指の付け根）・点 `marks`（目鼻耳・指先・足裏）・顔 68 点・約束事。
  - `cam.frameFov` と `cam.lens`（書き出し画像そのもののレンズ：縦の画角・縦横比・視線の軸の位置・サイズ）。
  - `props[i].parts`（箱・円柱の部品）。
- **画角を書き出し枠基準に**：画角スライダーは書き出し枠の縦の画角になり、書き出しは窓の大きさに依存しなくなった（窓 3 種類で 205.7 / 205.8 / 205.8px）。
  印の無い古いファイルの fov は約 0.84 倍（tan で換算）して読む近似。古いシーンを開くと構図がわずかに違うことがある。
- 仕様書 `docs/scene-format.md`、読み込みスクリプト `tools/blender_import.py`（空オブジェクトの階層・関節は回転モード YZX、骨の線・点・顔・小道具・カメラ）。
- **検証結果**（`docs/blender-verification.md`、Blender 5.2.1）：4 ケース（歩く／体型・手・配置／2人・小道具・俯瞰／全関節の乱数ひねり）、全 695 点で
  位置の最大差 0.0008mm、書き出し画像上の最大差 0.0005px。回転モードをわざと間違えると 415mm ずれて落ちることも確認。
  再実行は `tests/blender/make_cases.js` → Blender で `tests/blender/run_check.py`。見た目の確認用に `tests/blender/sample_c3_two_props.blend`。
- 範囲外：体の表面（肌メッシュ）は形式に無いので、深度・法線・線画は他のツールで同じにならない。アーマチュアへの変換、Blender → アプリの逆向きは未対応。
- smoke_test に `skeleton` `lens` `propParts` `formatTag` `viewportFree` を追加。
