# シーン JSON の Blender 検証の結果（2026-10-30、v1.7）

requests/2026-10-30_データ形式の検証_Blender.md への回答。形式の仕様は `docs/scene-format.md`。

## 結論
- **v1.7 のシーン JSON（posedoll-scene 2.1）だけで、Blender に同じ骨格・ポーズ・カメラを組み直せる。**
  4 種類のシーン・全 695 点で、位置の差は最大 **0.0008mm**、書き出し画像上の位置の差は最大 **0.0005px**（合格の目安は 1mm・0.5px）。
- v1.6 までの JSON（形式 2.0）では組み直せなかった。理由は下の「見つかった問題」の 1〜4。v1.7 で直した。
- 体の表面（人体の肌メッシュ）は形式に入っていない。深度・法線・線画の画像は Blender では同じにならない（下の「範囲外」）。

## やり方
1. `tests/blender/make_cases.js`（Playwright）がアプリで 4 つのシーンを作り、`cases/*.scene.json`（アプリが保存するのと同じ JSON）と
   `cases/*.ref.json`（正解：全ノード・OpenPose の点・顔の 68 点のワールド座標と、書き出し画像上のピクセル位置）を出す。
   正解は「保存した JSON をアプリに読み直した状態」から取る（保存時の丸めの分を含めないため）。
2. `tests/blender/run_check.py` を Blender の中で実行。各ケースを新しいシーンに `tools/blender_import.py` で読み込み、
   Blender が計算した `matrix_world` を three.js の座標へ戻して比べ、画像上の位置は Blender 自身のカメラ計算
   （`world_to_camera_view`。センサー・シフトを含む）で出して比べる。比べ終えたシーンは消す。結果は `tests/blender/results.json`。
3. 対照実験：関節の回転モードをわざと間違える（YZX → XYZ）と、ランダムなひねりのケースで最大 415mm ずれて落ちることを確認（検証が鈍くない）。

| ケース | 内容 | 点の数 | 位置の最大差 | 画像上の最大差 | 平均 |
|---|---|---|---|---|---|
| c1_walk | 標準体型・プリセット「歩く」・斜め上から・832×1216 | 139 | 0.00069mm | 0.00047px | 0.00011px |
| c2_wave | 体型を変更・「手を振る」・手の形・指の開き・1344×768・枠の中の配置（右 25%・下 10%・130%） | 139 | 0.00078mm | 0.00044px | 0.00015px |
| c3_two_props | 2人（子供体型で座る）・椅子（回転）と柱（回転・不均一な拡大）・俯瞰・1024×1024 | 278 | 0.00070mm | 0.00028px | 0.00010px |
| c4_random | 全 47 関節を ±60° の乱数でひねる（可動域オフ）・腰の位置と人物の位置・身長 1.07・896×1152・配置（左 15%・上 20%・80%） | 139 | 0.00068mm | 0.00031px | 0.00009px |

点 = 骨格のノード 50（関節 47・headGroup・親指の付け根 2）＋ 点 21（鼻・目・耳・指先 10・足裏 6）＋ 顔 68。
差の大きさは 32bit の浮動小数（Blender の行列）の丸めの程度。Blender 5.2.1 LTS（Windows）で実行。

見た目の確認用に c3 のシーンを `tests/blender/sample_c3_two_props.blend` に保存した（Blender の「ファイル → アペンド」でシーンを取り込める）。

## 見つかった問題と直し方（v1.7）
1. **骨格がファイルに無い**（予想どおり）… 骨の長さ・親子・親指の付け根の向き・頭の大きさの拡大・目鼻耳と足裏の点の位置がコードの中だけにあった。
   → 保存時に `figures[i].skeleton` を付ける（体型を反映済みの `offset`、固定ノードの `rest`・`scale`、点 `marks`、顔 `face`、約束事）。
2. **約束事が文書に無い**（予想どおり）→ `docs/scene-format.md` に明文化。回転順の対応（three.js 'XZY' = Blender 'YZX'）も書いた。
3. **書き出し画像の構図が、保存した値だけでは決まらなかった**（予想外・重要）… `cam.fov` は画面のカメラの縦の画角で、
   書き出し枠はその画面の中の一部なので、**ブラウザの窓の大きさが変わると書き出し画像の構図が変わっていた**。
   同じシーン JSON を窓 3 種類で開いて書き出すと、首の点の縦位置が 114.8 / 178.5 / −19.5px（1216px の画像）とばらばらだった。
   → v1.7 で画角の意味を「書き出し枠の縦の画角」に変え（`frameFov: true`）、書き出しのカメラを窓の大きさに依存しない形にした
   （直した後は 205.7 / 205.8 / 205.8px）。画面のカメラは枠がその画角になるよう自動で合わせる。
   さらに他のツール向けに、書き出し画像そのもののレンズ `cam.lens`（fovY・aspect・視線の軸の位置 center・size）を付けた。
   - 印の無い古いファイルの `fov` は「画面の画角」なので、読み込み時に tan で約 0.84 倍して換算する（よくある窓の大きさでの見た目に合わせた近似）。
4. **小道具は種類名だけ**（予想どおり）→ `props[i].parts`（箱・円柱の部品の寸法と位置）を付けた。
5. 親指の付け根（予想 5）は 1 の `skeleton` の固定ノード `fL_thumbBase` / `fR_thumbBase` として入った。

## 範囲外・残り
- **体の表面の形**（人体の肌・人形の部品）は形式に入れていない。アプリの式（体型の倍率 → 球・角丸円錐の組み合わせ → 距離場）でしか作れないため。
  深度・法線・線画の画像を他のツールで作り直したいなら、メッシュの書き出し（glTF など）を別に足すのが近道。必要になったら要望に。
- 読み込みは空オブジェクトの階層（関節ごとに回転モード YZX）。Blender のアーマチュア（ボーン）への変換はしていない
  （ボーンは Y 軸が骨の向きという別の約束なので、回転の付け替えが要る）。Blender でポーズを直して戻す使い方をするなら次の課題。
- 逆向き（Blender → アプリ）は未対応。
- 検証の再実行: アプリを変えたら `node tests/blender/make_cases.js` で正解を作り直し、Blender で `run_check.py` を実行する。
